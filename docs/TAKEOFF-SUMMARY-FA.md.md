# جمع‌بندی Takeoff پروژه Travelix Flex

## هدف تحویل

ساخت یک قالب کلاسیک وردپرس برای فروش و معرفی تورهای مسافرتی که:

- صفحه اصلی آماده و فارسی/RTL داشته باشد.
- محتوا و طراحی آن بدون دست‌کاری PHP و CSS قابل مدیریت باشد.
- محصولات را از WooCommerce و مقاله‌ها را از نوشته‌های وردپرس بخواند.
- برای Gravity Forms، Bookly، WPML و شورت‌کد افزونه‌های دیگر جایگاه استاندارد داشته باشد.
- هدر، فوتر، منوها، موبایل و صفحات داخلی پایه را یکپارچه نگه دارد.
- خروجی‌ها را Escape و ورودی تنظیمات را بر اساس نوع داده Sanitize کند.

## تحلیل دو مرجع طراحی

### Canvas Finance

الگوهای مفید استخراج‌شده:

- نوار اطلاعات تماس جدا از منوی اصلی.
- هیروی روشن و متمرکز بر یک پیام و CTA اصلی.
- بلوک‌های اعتمادسازی کوتاه نزدیک ابتدای صفحه.
- بخش خدمات/مزیت‌ها با تکرار منظم کارت‌ها.
- فرم تماس برجسته، نظرات مشتری و CTA نزدیک فوتر.
- سلسله‌مراتب تایپوگرافی واضح و فضای سفید کافی.

### Doob Business Consulting

الگوهای مفید استخراج‌شده:

- هیروی تمام‌عرض با تصویر، لایه تیره و کنتراست بالا.
- کارت‌های مدرن با Hover کنترل‌شده.
- بخش فرایند مرحله‌ای، نمونه‌کار و نظر مشتری.
- استفاده محدود و هدفمند از گرادیان برای CTAها.
- ریتم عمودی زیاد و تفکیک واضح بخش‌ها.

### تصمیم طراحی Travelix

طرح جدید کپی هیچ‌کدام از نمونه‌ها نیست. معماری روشن و اعتمادساز Canvas با هیروی قدرتمند، کارت‌ها و گرادیان‌های کنترل‌شده Doob ترکیب شده و رنگ‌های آبی/سرخابی نسخه اولیه Travelix به‌عنوان هویت پیش‌فرض حفظ شده است.

## وضعیت قالب ارسالی قبلی

نقاط مثبت:

- پشتیبانی اولیه از WooCommerce و تصاویر محصول.
- کوئری امن محصولات و نوشته‌ها.
- اتصال اولیه به Gravity Forms، WPML و Elementor Location.
- هدر و فوتر یکپارچه و CSS ریسپانسیو پایه.

کمبودهای اصلی که در نسخه جدید رفع شدند:

- فقط چند Setting محدود در Customizer وجود داشت.
- متن‌ها، آیکن‌ها، ترتیب و فعال/غیرفعال بودن اکثر بخش‌ها ثابت بود.
- طراحی کارت‌ها بدون پنل تغییر فونت، رنگ، Radius، Padding و فاصله بود.
- کنترل جداگانه تایپوگرافی و فاصله‌های موبایل/تبلت وجود نداشت.
- تنظیمات صفحات بعدی از قبل تعریف نشده بود.
- حالت کاتالوگ قبلی به‌صورت پیش‌فرض خرید همه محصولات را غیرفعال می‌کرد.
- تنظیمات متنی ذخیره‌شده در قالب مسیر مشخصی برای WPML String Translation نداشتند.
- منوهای فوتر، قوانین، خدمات، جستجو و سبد خرید کامل نبودند.

## امنیت اجراشده

- خروج مستقیم فایل‌های PHP در صورت نبود `ABSPATH` متوقف می‌شود.
- صفحه تنظیمات فقط برای کاربر دارای `edit_theme_options` باز است.
- Settings API نانس ذخیره تنظیمات را مدیریت می‌کند.
- همه فیلدها بر اساس نوعشان Sanitize می‌شوند.
- URL، رنگ، عدد، ایمیل، Select و Shortcode مسیر Sanitization جدا دارند.
- خروجی URL، Attribute، Text و HTML در Context مناسب Escape می‌شود.
- SVGها از کتابخانه ثابت قالب می‌آیند و HTML دلخواه کاربر اجرا نمی‌شود.
- Queryهای وردپرس و WooCommerce محدود و بدون SQL سفارشی هستند.
- فقط مدیر قالب می‌تواند شورت‌کدهای فرم/رزرو را تنظیم کند.

## مواردی که عمداً داخل قالب نیستند

- ساخت Custom Post Type اختصاصی تور؛ محصول WooCommerce منبع اصلی است.
- نگه‌داری منطق پرداخت یا رزرو در قالب؛ این منطق باید متعلق به افزونه باشد.
- تغییر فایل‌های WooCommerce یا افزونه‌ها.
- ذخیره اطلاعات فرم یا مشتری توسط قالب.
- لایسنس یا فایل افزونه‌های تجاری.

این جداسازی باعث می‌شود با تعویض ظاهر سایت، اطلاعات تجاری و رزرو از بین نرود.

## معیار پذیرش قبل از انتشار واقعی

- نصب و فعال‌سازی ZIP روی Staging با همان نسخه PHP و WordPress هاست.
- ذخیره یک‌باره تنظیمات قالب.
- تست یک محصول ساده، متغیر و تخفیف‌دار.
- تست Gravity Forms و Bookly با ارسال آزمایشی.
- تست WPML برای فارسی و انگلیسی.
- تست Checkout در حالت عادی و Catalog Mode در حالت فعال.
- تست Chrome، Firefox، Edge و Safari جاری.
- تست عرض‌های 360، 390، 768، 1024 و 1440 پیکسل.
- بررسی کش، HTTPS، ایمیل‌های وردپرس و دسترسی فایل‌ها.
